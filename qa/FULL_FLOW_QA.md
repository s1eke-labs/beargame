# Beargame 全流程质量验证

日期：2026-10-10。目标版本：v6.3.3。

## 发布检查入口

在项目目录运行 `npm run verify:release`。

这会依次执行语法检查、全部自动测试、静态构建、资源引用检查，以及正常操作推进回放。任一步失败都会以非零退出码终止。只验证脚本不能代替设备实测。

`npm run test:campaign` 可单独执行长期回放；详情见 `campaign/README.md`。

## 本次检查结果

发布检查以退出码 0 完成：689 项自动测试全部通过，静态构建及 90 个文件、180 个资源/模块引用验证通过；15 条阶段/分支结果（14 个连续阶段加 1 条轮回分支）共 51,106 次操作均精确匹配期望存档。

## 正常操作链路

从空档 seed 17 开始，不注入资源、研究或解锁标记。14 个连续阶段加一条独立轮回分支，共 51,106 次成功的公开操作，检查导出存档精确一致及校验和。覆盖生产、仓储、制作、研究、商旅、祈愿、工业自动化、首次太空发射、灵鹿/天角鹿与时晶、时空物理、穿越、月面采矿、轮回和挑战开始/退出。

大部分等待通过游戏公开的离线结算接口压缩。早期测试策略存在粮食赤字，单独在线测试时确实出现饥饿，不能把这些离线阶段当作持续在线生存证明。随后通过正常分工、食圃和水渠修正；工业、核能、太空和时光检查点均通过完整 800 秒在线年测试，保留全部居民。没有宣称最优节奏或全挑战通关。

## 本轮修复与回归

- 早期探索商旅页遗漏使馆操作。
- 祈愿产生超出存档范围的结果时，在消耗信仰前拒绝。
- 极限年份及自动熔炉失败时原子回滚，保留撤销收据和防重复随机收益状态。
- 时间推进受控失败时自动暂停，仅提示一次，保留可导出的进度。
- 探索菜单跳转不再留下重复的浏览器返回记录。
- 无星长夜、和平山林、时流不足、转化容量已满时，按钮状态与引擎执行条件一致。
- 顶层祈愿、太空、挑战卡片使用同一套权威条件，避免航路尚未抵达等状态不一致。
- 挑战选择有独立的无障碍名称，重复说明已去重。

相关回归测试均为 `full-flow-*.test.mjs`。极限值和挑战条件使用明确标注的合成测试数据，与正常操作回放分开。

## 独立后期条件审计

`endgame-audit/` 保留可复现的合成条件审计。1,679 个目录引用可解析；60 项受支持研究和 34/35 项太空项目经过容量/条件验证。高知识需求由数据中心扩容解决，反物质需求由额外容纳设施解决。最后一项太空项目单独使用 25,000 传承的合成继承场景证明容量可满足，不能视作正常赚取这些传承的流程证明。13 项时光设施的首次购买条件亦经过检查，其中三项单独设置年份、挑战或业力条件。

可从项目目录运行 `node qa/endgame-audit/static-gates.mjs --checkout .`；完整重跑顺序为 static-gates、capacity-witness、targeted-capacity、late-time-predicates、ui-contract。可用 `--output-dir` 指向另一个已存在目录；后续脚本读取该目录内前序生成的结果。此审计会补充资源并压缩旅行，仅证明条件与容量，绝不作为自然通关证据。

## 未覆盖与保证边界

- 未使用实体 iPhone、iOS Safari 或 Android 真机。
- 未穷举所有随机种子、政策组合、所有挑战完成路径和所有旧存档来源。
- 压缩离线回放不是持续在线全程，也不是平衡性或真实等待时长测评。
- 性能测量为 Node CPU 与有限浏览器操作，不能替代低端设备压力测试。

结论应限定为已测试关键链路可重复通过；不能承诺所有环境和所有存档绝无问题。
